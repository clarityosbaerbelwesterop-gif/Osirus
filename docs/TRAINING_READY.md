## Gate status: **TRAINING_READY = FALSE**

This document is the living tracker for the 18-checkbox training gate defined in master spec § 24. It evaluates every checkbox strictly against evidence in the repository (path/PR/branch cited per row). No checkbox is marked YES unless it is fully implemented **and** verifiably exercised. Scaffolds that are built and tested but never run against real infrastructure are marked PARTIAL, not YES.

**Status vocabulary**

- **YES** — fully satisfied and demonstrable in production / in the repo (evidence: path/PR).
- **PARTIAL** — scaffold/implementation exists and is tested, but real execution is outstanding (e.g. eval runner exists but no measured benchmark run; decontamination implemented but no corpus processed; BudgetGuard tested but no real spend-guard run).
- **NO** — absent / not verified.
- **BLOCKED-BY-OWNER-DEFERRAL** — the owner deliberately moved Phase E (Stripe) to the end of the program (decision of 2026-10-02).
- **GATED-BY-DESIGN** — requires GPU spend / real execution that is only permitted after TRAINING_READY=TRUE plus explicit owner authorization. These boxes cannot flip before the gate partially flips first; they are the final verification step, not a defect.

**Important branch note:** all `ai-lab/` artifacts cited below live on the **isolated branch `ai-lab/foundation`** (HEAD `1edc48a67bfe022493566ae87de6155b535a2eec`), never on `main` — per hard gate 1 of `docs/ROUGE_RESEARCH_HANDOFF.md`, no Rouge/Quesnir/Darus/ai-lab code merges into `main`.

## What unblocks the gate

Ordered path from FALSE to TRUE:

1. **Phase E (Stripe) delivers #4–#6.** Owner-deferred to the end of the program: checkout/portal/webhooks, credit ledger (reservations/settlement/refunds/hard ceiling), weekly quotas. This is the single largest unblock — three checkboxes at once.
2. **Legal operator inputs (#3).** Owner supplies the 12 inputs per `docs/LEGAL_STATUS.md` § 3; counsel review; DRAFT banners come down.
3. **Observability work (#7).** Move from structured console logging to APM/OTel-grade observability adequate for training/spend/eval monitoring (spec § 17); fold in RT2-06 (operator-gated readiness detail).
4. **Artifact store + rollback (#12, #13).** Build the durable artifact/model store (fresh build per handoff) and implement + exercise rollback (checkpoint/dataset/registry restore).
5. **Close out the PARTIALs (#8–#11, #16, #17).** Real corpus through the dataset contracts with decontamination recorded; measured eval runs on the runner with honest baselines; Stage B smoke proving checkpoint+resume end-to-end on our stack; BudgetGuard guarding one real (small) spend; one live call through each `ModelBackend` fallback leg.
6. **Final verifications #14/#15/#18 only after partial flip + owner go.** RunPod real provisioning, H200 smoke test, and reproducibility double-run are GATED-BY-DESIGN: they consume GPU budget and are permitted only once the other boxes are YES and the owner authorizes in writing (BUDGET.md § 2). The gate flips to TRUE when 1–15 are YES-equivalent and the owner signs; 14/15/18 are then executed as the confirmation runs.

## Phase M readiness runbook (plan — no execution)

What happens after the flip, in order. Nothing in this section has been performed; it is the approved-shape plan assembled from `docs/ROUGE_RESEARCH_HANDOFF.md` (stages) and `ai-lab/infra/BUDGET.md` (budget flow).

1. **Stage A — Corpus contracts.** Provenance + licensing rules enforced, decontamination tooling run against every eval set, eval-set isolation verified. No training. First real use of checkboxes #8/#10.
2. **Stage B — Local smoke.** The SCP `model/` seed stack trains a tiny model end-to-end on a free-tier/CPU-adjacent budget; checkpoint + resume proven; eval spine wired. First real use of #9/#11. **Quasnir goes first** as the smallest model (1B-class initial scale target per `ai-lab/models/quasnir/model.config.ts`), before any Rouge/Darus scale discussion.
3. **Stage C — Eval first.** Rouge task suites (M59–M75, defined on experiment branches) graded by the Osirus verification engine by interface; baselines recorded honestly, including failures; pass@1 with full model/seed/config record per run.
4. **Stage D — Scale decision point.** Written proposal (data, budget, expected metrics, rollback) → owner signs → only then GPU provisioning.
5. **Budget flow for every GPU run (BUDGET.md §§ 2–5), without exception:**
   - **estimate** — `GpuProvider.quote(req)` computes worst-case cost from the profile catalog (`estimatedTotalUsd = hourly rate × maxRuntime`); quotes are pure computation, always free.
   - **approve** — estimate checked against `BudgetGuard` ceilings (`maxUsdPerRun`, `maxUsdTotal`); over ceiling → `BudgetExceededError`, no run; within ceiling → written owner (or owner-delegated budget) approval recorded with the experiment registry entry.
   - **run** — only after approval, within the recorded estimate and the mandatory `ShutdownPolicy` (`autoShutdownAfterMs` hard deadline, `maxRuntimeMs` ≤ deadline, ≤ 24 h `MAX_AUTO_SHUTDOWN_MS`; longer runs decompose into checkpointed segments with `parentId` resume lineage).
   - Runtime authorization triple must hold: `OSIRUS_TRAINING_READY === "true"` + API key from environment (never from the repo) + `dryRun === false`, else `NotAuthorizedError`. No agent may flip TRAINING_READY — owner decision, in writing.
6. **Stages E–G — Training, distillation, publication.** Each follows the Stage D proposal with its own gate; distillation uses the SCP teacher-client pattern (teacher output is data, never evidence of self-trained capability); publication only with measured results.
7. **Standing honesty rules throughout Phase M:** no fabricated runs/benchmarks/capability claims; foreign weights (DeepSeek, Qwen, …) never relabeled as self-trained (`selfTrained: false` enforced by contract); the DeepSeek 2T corpus never appears as a provenance source (it was never released); `ai-lab/*` never merges into `main`.
